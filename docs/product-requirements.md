# sp-ice-db Product Requirements

## 1. Overview

sp-ice-db is a macOS desktop application for building and maintaining image datasets used in generative AI image workflows. The app manages source image paths, generated training-image outputs, and classification metadata authored by both users and AI services.

The primary unit of work is a `workspace` file. A workspace stores image references, metadata, AI classification results, generation settings, and working-directory information so the user can pause and resume dataset preparation.

## 2. Target Users

- Artists and dataset curators preparing image sets for generative AI training.
- Users who need sentence-style image descriptions for tools such as Anima.
- Users who need tag-style captions for SDXL and related image training pipelines.
- Users who want to combine manual curation with AI-assisted classification.

## 3. Core Concepts

### Image Entry

An image entry represents one user-managed source image path. It should store:

- Absolute file path selected by the user.
- File existence and readability status.
- Optional display name.
- Optional notes.
- User-authored classification metadata.
- AI-authored classification metadata.
- Generated image outputs derived from the source.

### Classification Metadata

Each image entry can have two metadata origins:

- `user`: text or tags written directly by the user.
- `ai`: text or tags generated by an AI provider.

Each origin can contain two metadata formats:

- `sentence`: natural-language description suitable for description-first tools.
- `tags`: comma-separated or structured tags suitable for SDXL-style captions.

### Generated Training Images

Generated training images are files created from registered source images. The app should collect these files into a user-selected working directory and keep references to them in the workspace.

The first implementation may define the data model before implementing generation. Later versions can add generation engines, batch processing, and prompt templates.

### Workspace

A workspace is a saved project file containing:

- Workspace metadata.
- Source folder references.
- Source image entries.
- Classification metadata.
- AI provider configuration references.
- Working-directory path.
- Generated output records.

## 4. Functional Requirements

### 4.1 Workspace Management

The app must allow users to:

- Create a new workspace.
- Save the current workspace to a file.
- Open an existing workspace file.
- Track unsaved changes.
- Store workspace version information for future migrations.

Recommended file extension: `.spicedb`

Recommended internal format for the first version: JSON.

### 4.2 Image Path Management

The app must allow users to:

- Add one or more image file paths.
- Add image paths via file picker.
- Register source folders that can be rescanned when the original image data changes.
- Scan registered source folders for supported images.
- Scan source folders recursively.
- Remove image paths from the workspace.
- Detect missing or moved files.
- Display image previews when files are readable.
- Store absolute paths initially.

Future enhancement:

- Support relative paths based on workspace location.
- Support file fingerprinting to help recover moved files.

### 4.3 Manual Classification Data

For each image entry, the app must allow users to edit:

- User sentence description.
- User tag list.

Tag editing should support:

- Comma-separated input.
- Trimming whitespace.
- Preserving tag order.
- Basic duplicate detection.

### 4.4 AI Classification Data

The app must support requesting classification metadata from an AI provider.

Minimum expected workflow:

1. User configures an AI provider.
2. User selects one or more image entries.
3. User runs AI classification.
4. App sends image content or accessible image references to the provider.
5. App stores returned sentence and/or tag metadata under the `ai` classification fields.
6. User can review, edit, copy, or promote AI output into user-authored fields.

### 4.5 AI Provider Configuration

The app should support OpenAI-compatible APIs.

Configuration fields:

- Provider name.
- Base URL.
- API key reference.
- Model name.
- Request timeout.
- Optional custom headers.
- Whether image input is supported.

Security expectation:

- API keys should not be stored directly in workspace files by default.
- API keys should be stored in macOS Keychain or an app-level secure settings store.
- Workspace files may store a provider profile identifier.

### 4.6 Generated Image Collection

The app must allow users to select a working directory for generated training images.

The app should track:

- Output image path.
- Source image entry ID.
- Generation timestamp.
- Generation settings or preset ID.
- Status such as pending, generated, failed, or removed.

First milestone:

- Define the records and UI placeholders.
- Allow assigning a working directory.

Later milestones:

- Add image generation provider support.
- Add batch generation.
- Add retry and failure reporting.
- Add generated output preview grid.

## 5. Non-Functional Requirements

### macOS Experience

- Native macOS file picker behavior.
- Drag-and-drop support for image files in later versions.
- Clear dirty-state and save behavior.
- Fast browsing for hundreds or thousands of image entries.

### Data Safety

- Workspace saves should be atomic where possible.
- Failed saves should not corrupt the previous workspace.
- Workspace version should be explicit.
- Unknown future fields should be ignored rather than causing complete load failure when practical.

### Privacy

- Source images should only be sent to an AI provider after explicit user action.
- The app should clearly distinguish local metadata from AI-generated metadata.
- Secrets should be kept out of workspace files.

## 6. Suggested Initial App Structure

The macOS implementation can be built as a native Swift/SwiftUI app.

Suggested modules:

- `WorkspaceStore`: load, save, migrate, and validate workspace files.
- `ImageLibrary`: manage image entries and file status.
- `ClassificationStore`: manage user and AI classification metadata.
- `AIProvider`: OpenAI-compatible API client and provider profiles.
- `GenerationWorkspace`: manage output directory and generated-image records.

## 7. Milestones

### Milestone 1: Workspace and Image Library

- Create native macOS app shell.
- Create workspace model.
- Save and load `.spicedb` JSON files.
- Add and remove image paths.
- Add and scan source folders.
- Show image list and basic preview.
- Edit user sentence and tags.

### Milestone 2: AI Classification

- Add AI provider settings.
- Add OpenAI-compatible request client.
- Send selected images for classification.
- Store AI sentence and tag metadata.
- Allow copying AI metadata into user metadata.

### Milestone 3: Generated Image Workflow

- Add working-directory management.
- Add generated output records.
- Integrate image generation provider or local workflow.
- Add batch generation and output review.

### Milestone 4: Dataset Export

- Export sentence captions.
- Export SDXL-style tag captions.
- Export image and caption pairs.
- Validate missing images and incomplete metadata before export.

## 8. Open Questions

- Should workspace paths be absolute only, or should the app support relative paths from the beginning?
- Which image generation providers or local engines should be supported first?
- Should generated training images be copied into the working directory, generated directly there, or both?
- Should AI classification support multimodal chat APIs only, or also specialized vision endpoints?
- What exact caption formats are required by the user's Anima and SDXL workflows?
